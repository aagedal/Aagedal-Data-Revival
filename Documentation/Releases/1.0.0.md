# Aagedal Data Revival 1.0.0

Published 2026-09-15, version 1.0.0 is the first public release of Aagedal Data
Revival. It is available from the
[GitHub Release](https://github.com/aagedal/Aagedal-Data-Revival/releases/tag/1.0.0)
for Apple silicon Macs running macOS 14 or newer.

> [!WARNING]
> Do not run the currently published 1.0.0 binary. A fresh download matched the
> digest below, but macOS rejected the app and bundled executables during code-
> signature verification. The tagged source remains available; wait for a
> corrected release before using a binary.

## Highlights

- Image owned SD, microSD, and CFexpress cards through temporary, path-specific,
  read-only macOS authorization; no privileged helper or background service is
  installed.
- Resume interrupted GNU ddrescue imaging with source-identity validation,
  mapfile progress, cancellation, remount, and eject controls.
- Recover JPEG and common camera RAW families from existing disk images or newly
  created card images using the bundled PhotoRec engine.
- Review persistent recovery sessions, validation labels, Quick Look previews,
  filters, and results before collision-safe export.
- Keep all card contents and recovery results local. Version 1.0.0 has no
  analytics, account, cloud storage, or automatic updater.
- Inspect bundled engine versions, licenses, notices, checksums, and exact
  corresponding source in the application bundle.

## Download verification

The published asset is `Aagedal_Data_Revival_1-0-0.zip`.

```text
SHA-256: d577b05504db038adf3b765ec75765917bb7f570f86dfd163c382a325a0f0d50
```

Verify it from Terminal with:

```sh
shasum -a 256 Aagedal_Data_Revival_1-0-0.zip
```

The release tag is `1.0.0` and points to commit
`16e0a7da550ee056b68fbb5558b0f357c84d6795`.

Post-publication verification on 2026-09-15 confirmed that the archive reports
version 1.0, build 1, is arm64-only, contains the expected recovery engines and
corresponding source, and carries a stapled notarization ticket. However,
`codesign --verify --deep --strict` rejects the app, PhotoRec, and ddrescue
signatures, and the signed-bundle audit fails at PhotoRec. The ZIP was extracted
independently with `ditto` and `unzip`; both methods produced identical app
executable hashes and the same verification failure.

## Known limitations

- Version 1.0.0 supports Apple silicon Macs running macOS 14 or newer.
- MOV/MP4 recovery, metadata-aware filesystem recovery, original filenames, and
  original directory reconstruction are not included.
- Representative CR2, NEF, ORF, and PEF fixtures recover byte-for-byte. The
  tested ARW, RAF, RW2, and X3F candidates retain trailing source bytes.
- A readable preview does not prove full camera RAW sensor-data integrity.
- Fragmented, truncated, overwritten, or flash-erased files may be partial or
  unrecoverable.

Recovery is best-effort. Stop using the affected card, preserve it, and store
the card image and recovered files on another physical device. See the
[support policy](../../SUPPORT.md), [privacy statement](../../PRIVACY.md), and
[complete changelog](../../CHANGELOG.md).
