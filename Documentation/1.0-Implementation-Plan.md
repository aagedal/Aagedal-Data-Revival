# Data Revival 1.0 implementation plan

Last reviewed: 2026-09-13

## Release definition

Version 1.0 is ready when a user on a clean, supported Apple silicon Mac can image an owned
SD, microSD, or CFexpress card without writing to it, recover JPEG and supported
camera RAW files from that image, review honestly qualified validation results,
and export selected files without installing command-line tools.

MOV/MP4 recovery and metadata-aware FAT32/exFAT recovery are not part of 1.0.
The product and documentation must not imply otherwise.

## Current baseline

- [x] Native macOS application and Release configuration compile.
- [x] Raw-image PhotoRec scans support JPEG and common camera RAW families.
- [x] Recovery sessions persist and retain partial results after cancellation or
  interruption.
- [x] Recovered files can be filtered, previewed, validated, and exported without
  overwriting existing files.
- [x] Removable whole disks are discovered read-only.
- [x] New and resumed ddrescue image plans protect against source/destination
  collisions and validate source identity, capacity, sidecars, and mapfiles.
- [x] The automated foundation suite passes (30 tests as of this review).
- [ ] The complete card-to-export workflow works without Terminal or Homebrew.

## P0: required before 1.0

### 1. Physical-card imaging

- [ ] Add a narrowly scoped privileged helper with an authenticated IPC
  interface.
- [ ] Install and update the helper using Apple's supported Service Management
  mechanism.
- [ ] Unmount the selected whole card through Disk Arbitration before imaging.
  - [x] Implement non-forced whole-disk unmount, remount, and eject operations.
  - [x] Add a testable imaging coordinator that revalidates before and after
    unmount and restores the card when post-unmount validation fails.
  - [ ] Invoke the coordinator from the privileged imaging workflow.
- [ ] Re-resolve and revalidate the card identity immediately before privileged
  access.
  - [x] Implement and test the app-side re-resolution boundary.
  - [ ] Repeat validation inside the authenticated helper before opening the
    raw source, closing the final device-name reuse race.
- [ ] Open the source read-only and prevent source/output aliases.
- [ ] Connect the prepared imaging plan to the UI and run bundled ddrescue.
- [x] Parse and publish rescued, pending, and bad-sector progress from the
  ddrescue mapfile while the runner is active.
- [ ] Connect imaging progress to the UI after privileged execution is enabled.
- [ ] Preserve the image, mapfile, record, and logs after failure or cancellation.
- [ ] Support safe resume after app restart and device reconnection.
- [ ] Handle authorization denial, removal, sleep, destination exhaustion, read
  errors, cancellation, and helper failure explicitly.
- [ ] Remount or offer to eject the card safely after imaging.

### 2. Production recovery engines

- [x] Select and pin reviewed PhotoRec and GNU ddrescue versions.
- [x] Create reproducible arm64 engine builds; Intel/x86_64 is not a supported
  1.0 architecture.
- [x] Bundle `photorec` and `ddrescue` under `Contents/Helpers`.
- [x] Bundle or eliminate every non-system dynamic dependency and use only
  relocatable load paths.
- [x] Add an Xcode copy/sign phase with inner-to-outer signing order.
- [x] Record engine name, version, architecture, digest, origin, and scan arguments in session
  metadata.
- [x] Include exact license texts, copyright notices, build inputs, and
  corresponding source/source offer.
- [ ] Pass `Scripts/audit-app-bundle.sh` on the signed archive.
- [x] Verify that a Release build never searches Homebrew, MacPorts, or
  `/usr/local`.

### 3. Recovery-quality benchmark

- [ ] Create versioned, non-sensitive fixtures for quick-formatted FAT32 and
  exFAT images.
- [ ] Cover representative JPEG and Canon, Nikon, Sony, Fujifilm, Olympus,
  Panasonic, Pentax, and Sigma RAW files.
- [ ] Cover contiguous, fragmented, truncated, corrupt-metadata, and overwritten
  cases.
- [ ] Compare recovered files with known originals using byte hashes.
- [ ] Test cancellation/resume, paths containing spaces, card removal, read
  errors, and a full destination.
- [ ] Publish the supported-format matrix and measured limitations.
- [ ] Define an acceptance threshold and make the benchmark a release gate.

### 4. Licensing and distribution

- [ ] Complete a license review for the app, PhotoRec, ddrescue, and every bundled
  dependency.
- [ ] Document how corresponding source and notices accompany each binary
  release.
- [ ] Enable and verify the hardened runtime and least-privilege entitlements.
- [ ] Sign the app, helper, engines, and libraries with Developer ID identities.
- [ ] Archive, notarize, staple, and verify the distribution artifact.
- [ ] Test Gatekeeper installation and first launch on a clean Mac.

### 5. Product truthfulness and data lifecycle

- [ ] Remove prototype and experimental labels once their corresponding release
  gates pass.
- [x] Remove the sample MP4 result and claims of footage/video recovery from the
  1.0 interface and documentation.
- [x] Estimate and check space for both the card image and recovered output.
- [x] Add reveal-in-Finder and recoverable session cleanup controls.
- [x] Persist source identity, source size, scan configuration, and engine
  provenance in every new scan session.
- [x] Preserve honest JPEG, RAW-preview, unchecked, and partial validation labels.

## P1: release engineering and polish

- [ ] Add a production application icon and complete bundle metadata.
- [x] Add CI for Swift tests and an unsigned Release build.
- [ ] Add the signed-bundle audit to release CI after production engines and
  signing identities are configured.
- [ ] Add UI tests for the image-scan, session-reopen, filtering, preview, and
  export paths.
- [ ] Test arm64 builds on Apple silicon hardware for every supported macOS major
  version.
- [ ] Complete accessibility, keyboard navigation, VoiceOver, contrast, and
  reduced-motion checks.
- [ ] Add a changelog, support information, privacy statement, release checklist,
  and rollback procedure.
- [ ] Choose and document an update/distribution channel.

## Explicitly deferred until after 1.0

- MOV/MP4 and camera-specific fragmented-video reconstruction.
- Metadata-aware FAT32/exFAT recovery of original names and directories.
- Claims of full sensor-data integrity for camera RAW files.
- Filesystems, media types, and recovery engines outside the published support
  matrix.

## Final release gate

- [ ] All P0 items are complete.
- [ ] All automated tests and the recovery benchmark pass from a clean checkout.
- [ ] The signed, notarized arm64 artifact passes the bundle audit.
- [ ] A clean-machine card-to-export acceptance test passes without external
  recovery tools.
- [ ] No unresolved issue can write to the source card, misidentify a device,
  overwrite user data, or materially overstate recovery results.
- [ ] `MARKETING_VERSION` is 1.0, the build number is unique, release notes are
  final, and the release commit is tagged.
